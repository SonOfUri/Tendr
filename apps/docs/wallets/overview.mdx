title: 'Wallets and passkeys'
description: 'Separate signing in from the key that authorizes movement of store funds.'
---

Your Tendr identity, store membership and wallet are separate records. Signing in on another device returns the same identity and stores. A missing local passkey must not create a different wallet.

| Credential               | Purpose                                             |
| ------------------------ | --------------------------------------------------- |
| Login passkey            | Sign in and confirm sensitive dashboard changes     |
| Dedicated wallet passkey | Authorize transactions from the store's live wallet |

Email sign-in establishes your Tendr login. It does not recreate or replace a wallet signing credential.

[Test mode](/testing) uses a separate Tidepool wallet and dedicated passkey. Its testnet balances are separate from Live, and wallet-key recovery is not available in Test mode yet.

Save [login recovery codes](/security/login-recovery) while you still have a working login passkey. A saved code plus fresh email verification lets you replace lost login passkeys while preserving the same account and stores.

## Current live wallet

A P-256 passkey controls a balance in NEAR Intents. The displayed `0x…` account ID is derived from the wallet key. It is not a named `business.tendr.near` account or a general EVM receiving address.

Setup registers the dedicated credential, then proves possession during activation. Resume unfinished activation with the existing credential.

<Warning>
  The native live wallet has one owner. Every enabled wallet passkey and recovery kit has full
  control of the wallet. Additional keys are not multisig or shared approval.
</Warning>

## Another device

Synced passkeys can be available on devices using the same supported credential provider. Availability depends on provider and device settings. Cross-device authentication may also let your phone approve a request on another computer.

If the wallet credential is unavailable, you can still sign in and view the same store. Transactions require a device or credential provider holding the wallet passkey.

In **Live wallet → Devices & recovery**, create another wallet passkey on the new device. Prove
it works, then approve the pending request with an existing wallet passkey. You can approve from
your old device after comparing the key fingerprint. Wait for the request to show **Confirmed**.

Creating another login passkey does not add a wallet signing key. Your wallet address stays the
same when you add or remove wallet passkeys. See [wallet recovery](/wallets/recovery) to prepare
for losing every device.
