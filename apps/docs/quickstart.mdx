title: Accept your first payment
description: Create a test checkout from your server, open the hosted page, and verify the result.
---

Use the hosted API at `https://api.usetendr.tech`. You need a Tendr store with test payment setup completed, a test secret key, and a publicly reachable HTTPS webhook endpoint.

<Tip>
  Using WooCommerce? [Download and install the Tendr plugin](/integrations/woocommerce) from your
  WordPress admin. It connects your store and handles API keys and webhooks automatically.
</Tip>

## 1. Create a test API key

Select your store and Test mode in the dashboard. Open **Wallet**, create its dedicated Test passkey and complete activation. Choose your settlement token, then open API keys and create a key with `sessions:write` and `sessions:read`. Keep it on your server as `TENDR_SECRET_KEY`. It begins with `tdr_test_` and is shown once.

## 2. Register your webhook

In the dashboard's webhook settings, add your HTTPS endpoint and subscribe to `payment.succeeded` and `checkout.session.expired`. Save its signing secret separately. [Verify every delivery](/security/webhook-signatures) before changing an order.

## 3. Create a checkout session

For TypeScript or JavaScript on Node.js 22+, install the public SDK in your server application:

```bash
npm install @usetendr/sdk
```

Set `TENDR_SECRET_KEY` in your server's environment. Use the price from your order database and
reuse the same idempotency key when retrying the same request. Other server languages can use
the equivalent HTTP request below.

<CodeGroup>

```typescript TypeScript
import { TendrClient } from '@usetendr/sdk';

const apiKey = process.env.TENDR_SECRET_KEY;
if (!apiKey) throw new Error('Set TENDR_SECRET_KEY on your server');
const tendr = new TendrClient({ apiKey });

const created = await tendr.checkoutSessions.create(
  {
    amount: '25.00',
    amount_currency: 'USD',
    external_ref: 'order-1042',
    success_url: 'https://shop.example/orders/1042',
    cancel_url: 'https://shop.example/cart',
    line_items: [{ name: 'Everyday T-shirt', quantity: 1, unit_amount: '25.00' }],
  },
  { idempotencyKey: 'order-1042-checkout-1' },
);

// Persist created.id and the complete created.url before redirecting the customer.
```

```bash cURL
curl --fail-with-body https://api.usetendr.tech/v1/checkout/sessions \
  -H "Authorization: Bearer $TENDR_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1042-checkout-1" \
  --data '{
    "amount": "25.00",
    "amount_currency": "USD",
    "external_ref": "order-1042",
    "success_url": "https://shop.example/orders/1042",
    "cancel_url": "https://shop.example/cart",
    "line_items": [
      { "name": "Everyday T-shirt", "quantity": 1, "unit_amount": "25.00" }
    ]
  }'
```

</CodeGroup>

The SDK uses `https://api.usetendr.tech` by default. Keep the client and its secret key on your
server; the customer only needs the returned checkout URL.

The response has this shape. These values are illustrative:

```json
{
  "id": "ses_example",
  "client_secret": "ses_example_secret_example",
  "url": "https://pay.usetendr.tech/ses_example#cs=ses_example_secret_example",
  "expires_at": "2026-11-10T16:30:00.000Z",
  "status": "PENDING_DEPOSIT"
}
```

## 4. Open checkout

Store the session ID against your order. Redirect to the returned `url` exactly, including its `#cs=` fragment. Do not reconstruct it or publish it in logs.

Pay with Tidepool test USDC or USDT on NEAR testnet, Base Sepolia or Solana devnet. Fund your customer wallet from the [Tidepool faucet](https://app.usetidepool.tech/faucet) and keep test NEAR, ETH or SOL for network fees. Connect the wallet or follow the deposit instructions and wait for verified settlement. Test tokens have no monetary value. See [Test payments](/testing); simulation controls are no longer part of hosted Test checkout.

## 5. Confirm payment

Verify the signature on `payment.succeeded`, deduplicate its event ID, and match its session and `external_ref` to your order. Check the mode and expected amount before fulfillment.

A success redirect or a popup closing is a UI signal. Your server determines whether the order is paid from the verified event and stored payment data.

<CodeGroup>

```typescript TypeScript
// Use the session ID saved with the order, not an ID supplied by the browser.
const session = await tendr.checkoutSessions.retrieve(created.id);
```

```bash cURL
curl --fail-with-body "https://api.usetendr.tech/v1/checkout/sessions/$SESSION_ID" \
  -H "Authorization: Bearer $TENDR_SECRET_KEY"
```

</CodeGroup>

The session read includes status, payments, refunds, settlement and your order reference. It does not return the original client secret.

Use `constructWebhookEvent` from `@usetendr/sdk/webhook` to verify the original request bytes before
parsing the event. Follow the [webhook guide](/security/webhook-signatures) for signature checks,
order reconciliation and duplicate delivery handling.
