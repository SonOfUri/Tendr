---
title: API overview
---

Base URL (local): `http://localhost:4000`

Auth: `Authorization: Bearer <api_key>` — see [API keys](/security/api-keys).

| Endpoint         | Auth                      | Description                                   |
| ---------------- | ------------------------- | --------------------------------------------- |
| `GET /v1/health` | none                      | Liveness check                                |
| `GET /v1/ping`   | secret or publishable key | Echoes the caller's merchant, mode and scopes |

Payment links and checkout themes have their own pages: [payment links](/api-reference/payment-links) and [themes](/api-reference/themes). Checkout endpoints (sessions, quotes, payments, refunds, webhook endpoints) are coming in the checkout project.

Errors:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "...",
    "requestId": "..."
  }
}
```

Errors any endpoint can return:

| Code                    | Status | When                                                                                                                                                                                                                |
| ----------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LIVE_MODE_UNAVAILABLE` | 403    | Live payments are not open yet on this platform. Going live and every write in live mode (a live key, a live session or link, a live connection) are refused. Live reads and everything in test mode work as usual. |
