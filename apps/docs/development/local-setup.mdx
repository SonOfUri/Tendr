---
title: 'Local development'
description: 'Run the test console and integration simulators from the Tendr repository.'
---

Local development uses simulated test payments. Start with the repository's current environment example and setup instructions.

```bash
nvm use
cp .env.example .env
npm install
docker compose -f infra/docker/docker-compose.yml up -d
npm run build --workspace=@tendr/contracts
npm run db:generate --workspace=@tendr/api
npm run db:migrate:dev --workspace=@tendr/api
npm run db:migrate:test --workspace=@tendr/api
npm run console:seed
npm run dev:console
```

The launcher checks that the API console uses local databases/providers. See the repository's `docs/api-console.md` for ports, prerequisites and simulator controls. Treat any seeded keys as local development credentials.

## WordPress

```bash
npm run dev:wordpress
```

The local store runs at `http://localhost:8894`. Production Tendr Connect requires a public HTTPS origin for both the storefront and webhook endpoint. After assigning a tunnel URL, connect or reconnect the plugin at that address. Keep the same tunnel during an in-progress payment.

Use isolated plugin test environments for automated tests; do not reset a connected store's database.

## Shopify simulator

```bash
npm run dev:shopify
```

This simulates the connector protocol; Shopify itself remains a hosted service.

## Preview these docs

```bash
npm run dev:docs
```

Open `http://localhost:3001`. The documentation preview does not start payment services.
