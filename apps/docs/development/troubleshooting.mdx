| Symptom                      | Likely check                                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `400 Bad Request`            | Read JSON error code/message and `details.field`; check decimal strings, required fields and unexpected fields |
| `401`                        | Wrong/revoked credential, expired session or required confirmation                                             |
| `403`                        | Wrong credential type, missing permission/scope or disabled live mode                                          |
| `404` for a known ID         | Store and test/live mode match the credential                                                                  |
| `ACCOUNT_NOT_READY`          | Activate wallet and set settlement in the correct mode                                                         |
| `IDEMPOTENCY_CONFLICT`       | Reused key with changed path/body/query                                                                        |
| Blank checkout frame         | Browser `frame-ancestors` error; current origin not registered                                                 |
| Paid in Tendr, order pending | Webhook destination, delivery attempts, signature and order matching                                           |
| No invoice email             | Address, spam folder, verified sender setup and rate limits                                                    |
| AI unavailable               | Provider configuration, availability or rate limit; keep ordinary checkout usable                              |

## Changed WordPress address

Reconnect to the same store from WooCommerce's Tendr settings. Registering only a new checkout origin does not update the old webhook URL. Version 0.3.3 pauses checkout while the saved address is stale. Reconnecting starts in Test mode.

## Different device, same email

Sign in to the same identity and select the same store/mode. The wallet is tied to the store, not the browser. Wallet signing requires the dedicated wallet passkey; an email login does not supply it.

## TypeScript SDK

| Symptom                                       | What to check                                                                                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cannot resolve `@tendr/sdk`                   | Install `@usetendr/sdk` and update both main and `/webhook` imports. The old workspace name was not the public npm package.                       |
| `TendrClient is server-only`                  | Move client construction into a server route or backend job. Use the checkout URL or browser embed in the frontend.                               |
| Invalid `apiKey`                              | Supply a server secret key beginning with `tdr_test_` or `tdr_live_`. Load it in the server environment; the SDK does not read environment files. |
| Requests go to `/v1/v1/...`                   | Remove `/v1` from `baseUrl`, or omit the option to use the hosted API default.                                                                    |
| `SIGNATURE_INVALID` on every API request      | The key requires HMAC request signing, which SDK 0.2.0 does not generate. Use an HTTP integration implementing the configured signing policy.     |
| `TendrTimeoutError` or `TendrConnectionError` | Reconcile writes before retrying. Reuse the same saved operation key and identical input; the SDK does not retry automatically.                   |
| `TendrWebhookError`                           | Use the endpoint signing secret and original body bytes, preserve the signature header, and check the server clock.                               |

Use Node.js 22 or later. The webhook helper needs Node crypto. See the
[SDK guide](/sdks/typescript) for configuration, scopes and error types.

## Report an issue

Include the request ID, endpoint/method, HTTP status, mode, timestamp and non-secret resource ID. Do not send API keys, webhook secrets, full checkout URLs or invoice receipt tokens. A screenshot alone may not show which request failed.
