# Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the codebase deployable as one production environment on `pay.` / `app.` /
`api.usetendr.tech`, with real email, GCS assets, Terraform for Railway and GCP, and live mode built
but held behind `LIVE_MODE_ENABLED` (and gasless held off in live behind `GASLESS_LIVE_ENABLED`).

**Architecture:**
- The API changes URL shapes and gains two switches, a Resend mailer and stricter production env
  checks.
- The web app's middleware routes by `Host` and rewrites root-form shopper paths onto the existing
  `/pay/...` pages.
- The WooCommerce plugin learns an app base.
- Terraform gains the web service, domains, the bucket and remote state.
- Nothing is applied or pushed; the runbook lists the outside steps.

**Tech Stack:**
- Node 22 TS ESM, Fastify 5, Prisma 6, zod, Vitest
- Next.js 15 middleware
- WooCommerce PHP (wp-env in Docker)
- Terraform (`hashicorp/google ~> 6.0`, `terraform-community-providers/railway ~> 0.6`), run through
  the `hashicorp/terraform` Docker image

**Spec:** `docs/superpowers/specs/2026-10-31-deploy-design.md`

## Global Constraints

- Hosts:
  - `CHECKOUT_BASE_URL=https://pay.usetendr.tech`
  - `WEB_URL=https://app.usetendr.tech`
  - `API_BASE_URL=https://api.usetendr.tech`
  - `CORS_ORIGINS=https://app.usetendr.tech`
  - `WEBAUTHN_RP_ID=usetendr.tech`
  - `WEBAUTHN_ORIGINS=https://app.usetendr.tech`
- URL shapes:
  - session `${CHECKOUT_BASE_URL}/${id}`
  - link `${CHECKOUT_BASE_URL}/${merchant}/${link}`
  - refund address `${CHECKOUT_BASE_URL}/${id}/refund-address?t=…`
- Old `/pay/…` URLs keep working: on the pay host they get a 308 to the root form; on any other
  host they behave as today.
- Hosts are compared using values from env (`CHECKOUT_BASE_URL`, `WEB_URL`), never hard-coded
  hostnames in code.
- New env vars are added to `turbo.json` `globalPassThroughEnv` and to `.env.example`, with a
  comment in each.
- `LIVE_MODE_ENABLED` and `GASLESS_LIVE_ENABLED` default to `false`. `FEE_SWEEP_ENABLED` stays
  `false`.
- No plaintext secret in Postgres, the repo, a URL or a log line. Outside API keys are env vars.
- No software installed on the host; tooling runs in Docker.
- The dev DB is `tendr_foundation`, the test DB `tendr_foundation_test`; never touch `tendr`. Only
  one test process runs at a time on the shared test DB.
- Commits carry no `Co-Authored-By: Claude` or "Generated with Claude Code" lines.
- Nothing is pushed, applied, or sent to an outside service.

## Review Focus

1. **A live request while the switch is off.** A live secret key, a dashboard request in live mode,
   or a WooCommerce live call is refused with `403 LIVE_MODE_UNAVAILABLE` on every write. Reads
   still work. Test (Task 2): a live-key `POST /v1/checkout/sessions` gets 403.
2. **A merchant slug that equals a pay-host path** (`preview`, `v1`, `downloads`, `privacy`,
   `terms`, `pay`). Signup or link creation refuses it. Test (Task 1).
3. **A shopper opens an old link `https://pay.usetendr.tech/pay/acme/coffee?x=1`.** The redirect
   keeps the query string. Test (Task 5).
4. **The embed and the wallet popup on the root-form URL.** The session id is still found, so
   payment completes and frames aren't refused. Test (Task 5): every matcher accepts both forms.
5. **A mail template the Resend renderer forgets.** Every `MailTemplate` value renders a non-empty
   subject and text with no `{…}` left in it. Test (Task 4) loops over `MailTemplateValues`.
